# Defold の設計 {#the-design-of-defold}

Defold は、次の目標を掲げて作られました。

- ゲーム開発チームがすぐに使える、必要なものをすべて備えたプロ向けの制作プラットフォームであること。
- シンプルでわかりやすく、ゲーム開発でよくあるアーキテクチャーやワークフローの問題に明確な解決策を提供すること。
- 改良を繰り返すゲーム開発に最適な、極めて高速な開発プラットフォームであること。
- 実行時に高いパフォーマンスを発揮すること。
- 真のマルチプラットフォーム対応を実現すること。

エディターとエンジンは、これらの目標を達成できるように注意深く設計されています。他のプラットフォームを使った経験がある場合、Defold の設計上の選択の一部は、慣れ親しんだものとは異なるかもしれません。たとえば、次のような違いがあります。

- リソースツリー（resource tree）とすべての名前を静的に宣言する必要があります。このため最初は多少の手間がかかりますが、長期的には開発プロセスを大きく助けます。
- シンプルでカプセル化されたエンティティ間では、メッセージによる通信であるメッセージパッシング（message passing）を推奨しています。
- オブジェクト指向の継承はありません。
- Defold の API は非同期です。
- レンダリングパイプライン（rendering pipeline）はコードで制御され、完全にカスタマイズできます。
- Defold のリソースファイルはすべてシンプルなプレーンテキスト形式で、Git でのマージや、外部ツールでのインポートおよび処理に最適な構造になっています。
- リソースを変更して、実行中のゲームにホットリロード（hot reload）できます。これにより、改良や実験を極めて高速に繰り返せます。
