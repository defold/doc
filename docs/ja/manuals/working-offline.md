# オフラインでの作業 {#working-offline}

Defold は、ほとんどの場合、インターネット接続なしで作業できます。ただし、次のようにインターネット接続が必要な場合もあります。

* 自動更新
* 問題の報告
* 依存関係の取得
* ネイティブ拡張のビルド


## 自動更新 {#automatic-updates}

Defold は、新しい更新があるかどうかを定期的に確認します。更新の確認は [公式ダウンロードサイト](https://d.defold.com) に対して行います。更新が見つかると、自動的にダウンロードされます。

インターネットに接続できる時間が限られていて、自動更新が始まるのを待ちたくない場合は、[公式ダウンロードサイト](https://d.defold.com) から新しいバージョンの Defold を手動でダウンロードできます。


## 問題の報告 {#reporting-issues}

エディターで問題が検出されると、その問題を Defold の問題追跡システムに報告するかどうかを選択できます。この問題追跡システムは [GitHub 上でホストされている](https://www.github.com/defold/editor2-issues) ため、問題を報告するにはインターネット接続が必要です。

オフラインで問題が発生した場合は、後でエディターの [Help メニューにある Report Issue オプション](/manuals/getting-help/#report-a-problem-from-the-editor) を使って手動で報告できます。


## 依存関係の取得 {#fetching-dependencies}

Defold は、[ライブラリプロジェクト（Library Projects）](/manuals/libraries/) と呼ばれる仕組みを使って、開発者がコードやアセットを共有できるようにしています。ライブラリは zip ファイルで、オンラインの任意の場所でホストできます。Defold のライブラリプロジェクトは、通常、GitHub やその他のオンラインのソースコードリポジトリで見つかります。

プロジェクトでは、ライブラリを [プロジェクト設定でプロジェクトの依存関係として追加](/manuals/project-settings/#dependencies) できます。依存関係は、プロジェクトを開いたとき、または *Project* メニューから *Fetch Libraries* オプションを選択するたびにダウンロードまたは更新されます。

複数のプロジェクトでオフラインで作業する必要がある場合は、あらかじめ依存関係をダウンロードし、ローカルサーバーを使って共有できます。GitHub 上の依存関係は、通常、プロジェクトのリポジトリの Releases タブから入手できます。

![GitHub 上のライブラリの URL](images/libraries/libraries_library_url_github.png)

Python を使うと、ローカルサーバーを簡単に作成できます。

    python -m SimpleHTTPServer

これにより、現在のディレクトリにサーバーが作成され、`localhost:8000` でファイルが配信されます。現在のディレクトリにダウンロード済みの依存関係が含まれている場合は、それらを *game.project* ファイルに追加できます。

    http://localhost:8000/extension-fbinstant-4.1.1.zip


## ネイティブ拡張のビルド {#building-native-extensions}

Defold は、[ネイティブ拡張（Native Extensions）](/manuals/extensions/) と呼ばれる仕組みを通じて、開発者がネイティブコードを追加してエンジンの機能を拡張できるようにしています。Defold は、クラウドでビルドする仕組みによって、セットアップ不要でネイティブ拡張を使い始められるようにしています。

ネイティブ拡張を含むプロジェクトを初めてビルドすると、Defold のビルドサーバー上でネイティブコードがコンパイルされ、カスタムの Defold ゲームエンジンに組み込まれて、PC に返されます。このカスタムエンジンはプロジェクト内にキャッシュされます。ネイティブ拡張の追加、削除、変更を行わず、エディターも更新しない限り、その後のビルドで再利用されます。

ネイティブ拡張を含むプロジェクトでオフラインで作業する必要がある場合は、プロジェクトにカスタムエンジンのキャッシュ済みコピーが含まれるように、少なくとも1回はビルドを成功させておく必要があります。
