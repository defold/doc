# Defold ドキュメント日本語翻訳ガイド

このガイドは、Defold の日本語マニュアル、チュートリアル、FAQ、共有テキストを翻訳、更新する際に使います。[glossary.txt](glossary.txt) と併用してください。初版作成日: 2026-09-07。

調査時点の `docs/ja` には翻訳文書がありません。このガイドは既存の日本語訳の慣習を報告するものではなく、各言語の翻訳資料、リポジトリの共通規則、公式サイトの日本語技術文書を参考に、新しい日本語版の方針を定めたものです。

## 基本原則と参照の優先順位

読者が概念や操作を理解するための文章は、自然で正確な日本語にします。読者が画面で探す、入力する、コピーする文字列は正確に保持します。

- 技術的な内容、条件、制約、手順、対応バージョンは、対応する `docs/en` のファイルを基準にします。まず英語ファイル全体を読みます。
- 構造、コード、リンク、特殊なマークアップの扱いは、README とこのリポジトリの形式に従います。
- 日本語の説明に使う語彙と文体は、本ガイドと `docs/ja/glossary.txt` に統一します。
- UI のラベルは、説明対象のバージョン、表示言語、スクリーンショットに一致するものを使います。用語集の説明用の訳を UI の正式名称とみなしません。
- 用語集にない一般的な技術用語は、該当分野の公式の日本語文書で用例を調べます。他製品の機能や実装の違いを確認してから採用します。

外部の日本語文書や他言語の Defold 文書は、英語原文の内容を補ったり変更したりする根拠にはしません。英語原文に疑問がある場合は確認事項として記録し、日本語版だけに推測した仕様を追加しないでください。原文との内容の一致を重視する考え方は、[MDN の日本語翻訳ガイド][J1] でも確認できます。ただし、MDN 固有のコード翻訳やメタデータの規則は採用しません。

## 文体と説明の組み立て

標準的な日本語の「です・ます」調を使います。見出しや用語表の短い定義は体言止めでもかまいません。

- 操作手順は「選択します」「追加します」「設定します」のように書きます。禁止は「しないでください」、必要条件は「する必要があります」と明確にします。
- 英語の `you` を毎回「あなた」と訳しません。主体が明らかなら省略し、必要なら「ユーザー」「エディター」「エンジン」などを明示します。
- `we` は共同の作業なら「ここでは」、Defold 側の見解なら主体が分かる表現にします。「私たち」を機械的に挿入しません。
- 長い英文は意味のまとまりで文を分けられます。ただし、条件、因果関係、否定の範囲、例外、実行順序は保持します。
- 「〜することが可能です」より「〜できます」、「〜を行うことによって」より「〜すると」「〜して」を優先します。
- 「簡単に」「もちろん」「必ず」などを原文にない強調として追加しません。結果の保証や難易度を変えないでください。
- 一般的な補助表現は「できます」「ください」「たとえば」「すべて」を使います。漢字を増やすことを正確さと混同しません。

例:

| English | 日本語 |
|---|---|
| Select Add Game Object. | <kbd>Add Game Object</kbd> を選択します。 |
| You can change the position at runtime. | 実行時に位置を変更できます。 |
| This creates a new game world. | これにより、新しいゲームワールドが作成されます。 |
| Do not modify this value. | この値を変更しないでください。 |

## 義務、推奨、可能性、数量

| 原文の意味 | 日本語での表し方 |
|---|---|
| must / required | 必要があります / 必須です |
| must not | してはいけません / しないでください |
| should / recommended | 推奨します / することをお勧めします |
| should not | 推奨しません / 避けてください |
| can（能力や実行可能性） | できます |
| may（許可） | してもかまいません |
| may / might（可能性） | ことがあります / 可能性があります |
| cannot / unsupported | できません / サポートされていません |

`may not` が禁止なのか「〜しない可能性がある」なのかは文脈で判断します。大文字の規範語や警告の強さも保持します。

`only`、`all`、`each`、`at least`、`at most`、`before`、`after`、`until`、単数と複数が表す制約を省略しません。`more than` と `at least`、`less than` と `at most` の境界も区別します。日本語の数値、単位、範囲、既定値は英語原文と一致させ、独自に換算しません。

## 重要な概念の初出

各記事の最初の説明では、日本語の用語の後に英語を全角括弧で添えます。

- ゲームオブジェクト（game object）
- コンポーネント（component）
- コレクション（collection）
- ファクトリー（factory）
- コレクションプロキシ（collection proxy）
- 入力バインディング（input binding）

初出後は日本語の形を使い、英語を繰り返し付けません。記事を独立して読めるよう、別の記事では必要に応じて説明し直します。広く知られた語、製品名、API 名に不要な訳や読み仮名は付けません。

見出しを二重に並べる形式は避けます。「Collections コレクション」ではなく「コレクション」とし、必要な英語は本文の初出に置きます。見出し自体が API 名や正確な設定名の場合は原文を保持します。

## 意味を混同しやすい Defold 用語

- コレクションは配置や階層の定義です。コレクションのファイル、読み込まれたゲームワールド、ゲームオブジェクトのインスタンスを区別します。
- ファクトリーはゲームオブジェクトを生成します。コレクションファクトリーは現在のゲームワールドに内容を生成します。コレクションプロキシは別のゲームワールドを読み込みます。この違いは [英語のマニュアル](../en/manuals/collection-proxy.md) に従います。
- コレクション階層と、トランスフォームに影響する親子階層を区別します。親子関係の変更を、アドレスが変わることと説明しません。
- GUI ノードをゲームオブジェクトと呼び替えません。Godot のノード、Unity の GameObject、Unreal Engine の Actor も、比較の範囲を超えて同一視しません。
- Defold のプロトタイプはインスタンスの元となる定義です。一般的な試作品の意味や Unreal Engine のブループリントの仕組みを持ち込みません。
- リソースとアセット、プロパティと頂点属性、URL のフラグメントと描画のフラグメントを文脈で区別します。
- `runtime` は実行環境ならランタイム、時点なら実行時です。処理の所要時間を示す実行時間とは区別します。
- ビルド、コンパイル、バンドル作成、起動、公開は別の操作です。`build`、`bundle` などのコマンド名は翻訳しません。
- ホットリロードと Live Update、エディターのプレビューと実行中のゲームのスクリーンショット、エディターサーバーとエンジンサービスを区別します。
- 有効化、表示、初期化、削除、終了処理、アンロードは同義ではありません。実行順序やコールバックの条件を訳語だけから推測しません。

## UI ラベル、操作、キーボード

英語の UI を説明する原文やスクリーンショットでは、そのラベルを保持します。説明のための日本語を添えることはできますが、存在を確認していない日本語 UI 名に置き換えません。

- `<kbd>Add Game Object</kbd> を選択します。`
- `<kbd>Outline</kbd> ビューでゲームオブジェクトを選択します。`
- `<kbd>Properties</kbd> ペインで値を変更します。`
- `<kbd>Edit ▸ World Space</kbd> を選択します。`

設定リファレンスでは、項目名と値を UI や `game.project` に一致させ、説明を日本語にします。たとえば `Max Nodes` を項目名として保持し、説明では「ノードの最大数」と書きます。

日本語 UI を明示して説明する記事では、対象バージョンの実画面または公式の日本語ローカライズファイルで確認したラベルを使います。英語のスクリーンショットと併用する場合は初出に英語ラベルも示します。確認できないラベルは英語を保持します。他製品や他言語のローカライズから Defold のラベルを推測しません。

メニューやコマンドは原文の `<kbd>...</kbd>` を保持します。新しいメニュー経路を記述する際は `▸` で階層を区切ります。原文の強調記法や既存のメニュー表記を、翻訳だけのためにまとめて変更しません。

`<kbd>` の内容が通常の動作なら翻訳します。たとえば `<kbd>right-click</kbd>` は `<kbd>右クリック</kbd>`、`<kbd>drag</kbd>` は `<kbd>ドラッグ</kbd>` です。タグで囲まれているかだけで、翻訳するかどうかを決めません。

`Ctrl`、`Cmd`、`Shift`、`Alt`、`Enter` などのキー名、キーの組み合わせ、プラットフォーム別の違いは原文のまま保持します。日本語キーボード向けに推測でショートカットを書き換えません。

## コード、API、入力と出力

README に従い、コードブロックはコメントを含めて原文のまま保持します。

- Lua、C++、シェーダー、JSON、YAML、INI、シェル、コンソール出力などの内容を翻訳、整形、修正しません。文字列、コメント、空白、インデントも保持します。
- 関数、コールバック、名前空間、メッセージ、列挙値、フィールド、変数、識別子は保持します。例: `msg.post()`、`on_message()`、`set_parent`、`message_id`、`bean`。
- ファイル名、拡張子、パス、設定キー、環境変数、コマンド、オプションは保持します。例: `game.project`、`.collection`、`max_count`、`build-html5`。
- HTTP メソッド、ルート、ヘッダー、ステータスコード、エラーメッセージ、期待される出力は保持します。例: `POST /eval`、`Authorization: Bearer`、`success`、`duration_ms`。
- ASCII の引用符、ハイフン、コロン、スラッシュ、数字を全角文字やスマート引用符に置き換えません。
- コード内のコメントを日本語で補足する必要があれば、対応する説明文に含めます。コードだけ日本語の別バージョンを作らないでください。

英語のコメントやコンソール出力が残ることは、未翻訳の説明文が残ることとは異なります。翻訳漏れのチェックから、正確に保持すべき文字列を区別してください。

## Markdown、front matter、リンク

- YAML front matter の区切り、キー、構造を保持し、説明用の `title` と `brief` の値を翻訳します。識別子、パス、真偽値などの非文章の値は保持します。必要な引用符やエスケープも維持します。
- 見出しの順序とレベル、段落の対応、箇条書き、番号付きリスト、定義リスト、表の構造を保持します。手順の統合、削除、並べ替えはしません。
- 明示的なアンカーを保持します。例: `{#the-editor-views}`、`<a id="example">`。見出しを訳したために暗黙のアンカーが変わる場合は参照元との整合性を確認し、既存リンクを黙って別の断片に書き換えません。
- `::: sidenote`、`::: important`、閉じる `:::` は保持し、内側の文章を翻訳します。
- `:[components](../shared/components.md)` などのインクルード指示は、ラベルとパスを含めて保持します。通常の Markdown リンクとは区別します。
- コードフェンス、言語指定、インラインコードを保持します。HTML のタグ、属性、CSS クラス、テンプレートの変数やディレクティブも保持します。
- 通常のリンクの説明文と画像の代替テキストは翻訳します。API 名、製品名、UI 名などの文字列は保持します。
- リンク先 URL、参照リンクの識別子、相対パス、画像パス、クエリー、フラグメント、末尾のスラッシュは保持します。`/ja/` を独自に追加しません。
- 強調の範囲や表のセルを保ち、空白を強調記号の内側に入れません。日本語の句読点で Markdown の区切りを置き換えないでください。

例:

- `[Project settings](/manuals/project-settings/#debug)` → `[プロジェクト設定](/manuals/project-settings/#debug)`
- `[gui.clone()](/ref/gui/#gui.clone:node)` → そのまま保持します。
- `![Editor overview](images/introduction/editor.png)` → `![エディターの概要](images/introduction/editor.png)`

## 日本語の句読点、空白、数字

以下は説明文の規則です。コードや文字列リテラルの表記は変更しません。

- 句読点は「、」「。」を使います。見出しと短い用語セルには原則として句点を付けず、完全な文には付けます。
- 日本語の引用には「」を使い、引用の内側の引用には『』を使います。技術的な文字列には原文どおりバッククォートを使います。
- 補足や初出の英語には全角括弧を使います。例: コレクション（collection）。API 呼び出しの `()` は半角のままです。
- 日本語同士の語の間に空白を入れません。例: ゲームオブジェクト、コレクションプロキシ、レンダリングパイプライン。
- 半角の英単語や略語と日本語の間には、原則として半角スペースを入れます。例: `Defold の GUI コンポーネント`、`Lua スクリプト`、`2D グラフィックス`。括弧や句読点の内側には、この目的で空白を追加しません。
- インラインコードや英語の UI ラベルと周囲の日本語は、たとえば `` `game.project` を開きます ``、`<kbd>Properties</kbd> ペイン` のように区切ります。リテラルの内部は変更しません。
- 数字と助数詞は `3つ`、`2回`、`1フレーム` のように続けて書きます。単位は `60 fps`、`16 ms`、`128 MB` のように表し、原文の単位や精度は保持します。

1. 英語原文と API の説明で意味を確認し、用語集を検索します。英語の複数形、ハイフンの有無、大小文字だけが違う項目を重複して追加しません。

## 翻訳後の確認

1. 英語原文と対応させ、説明、条件、注意、例外、手順、表の行に欠落がないか確認します。
2. 義務と推奨、可能性と保証、否定、数量、範囲、単位、実行順序を確認します。
3. 用語集との一致、初出の英語併記、「です・ます」調、長音、句読点、空白を確認します。
4. コードブロックとコメント、インラインの技術的な文字列、UI ラベル、識別子、コマンド、入力と出力が保持されているか差分で確認します。
5. front matter、見出し、リスト、表、定義リスト、コードフェンス、HTML、インクルード、特殊なブロックを確認します。
6. リンク先、参照リンクの識別子、アンカー、画像パスを比較します。日本語化でリンク先の解決が変わる場合は記録して確認します。
