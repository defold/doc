# Настанови з перекладу документації Defold українською

Ці настанови створено на основі всіх наявних українських матеріалів у `docs/uk`. Для швидкого пошуку відповідників використовуйте `docs/uk/glossary.txt`.

Український корпус невеликий і складається з давніших базових посібників та новіших матеріалів про автоматизацію. У старіших файлах були друкарські помилки, залишки англійської прози й різні апострофи. Такі випадки не є зразком стилю. Орієнтуйтеся на повторювану термінологію базових посібників, узгоджену з мовою новіших матеріалів.

## Основне правило

Перекладайте пояснювальну прозу природною, чіткою українською. Зберігайте оригінальне написання всього, що читач має точно впізнати, ввести або викликати в Defold: назв продуктів, елементів інтерфейсу, символів API, функцій, повідомлень, ідентифікаторів, імен файлів, шляхів, команд, полів, ключів конфігурації, значень і URL.

Практична перевірка:

* якщо фраза пояснює поняття або дію, перекладіть її;
* якщо це точний рядок з інтерфейсу, коду, консолі, файлу чи протоколу, залиште його без змін і за потреби додайте українське пояснення.

## Тон і звертання

Пишіть безпосередньо, доброзичливо й по-діловому.

* Звертайтеся до читача на `ви`: `виберіть`, `використовуйте`, `перевірте`, `зауважте`.
* Не переходьте на `ти` й не змішуйте однину та множину в межах одного матеріалу.
* У процедурах використовуйте короткі наказові речення й активний стан, коли це природно.
* Не калькуйте англійську будову речення. Перебудовуйте фразу, якщо дослівний переклад звучить неприродно.
* Віддавайте перевагу `дає змогу` або `можна`, а не повторюйте `дозволяє` в кожному реченні.
* Використовуйте `будь ласка` лише там, де воно справді потрібне; технічна інструкція не має бути надмірно церемонною.

Приклади бажаного тону:

* `Виберіть <kbd>Help ▸ Open Editor Server</kbd>, щоб відкрити домашню сторінку.`
* `Зачекайте, доки проєкт відкриється.`
* `Не відкривайте доступ до порту через публічну адресу.`

## Ключова термінологія

Використовуйте послідовно:

| English term | Українська форма |
|---|---|
| engine | рушій |
| editor | редактор |
| application / app | застосунок у документації Defold; `програма` для виконуваної програми або усталеного терміна зовнішнього продукту |
| project | проєкт |
| game object | ігровий об’єкт |
| component | компонент |
| collection | колекція |
| bootstrap collection | стартова колекція |
| collection proxy | проксі колекції |
| script | скрипт |
| Tile Map | карта плиток; точну назву типу `Tile Map` не перекладати |
| runtime | середовище виконання / під час виконання |
| message passing | передавання повідомлень |
| send a message | надіслати повідомлення |
| message queue | черга повідомлень |
| build | збирання; `збірка`, коли йдеться про результат |
| output | виведення |
| log | журнал |
| endpoint | кінцева точка |
| route | маршрут |
| screenshot | знімок екрана |
| timeout | тайм-аут |
| assertion | твердження |

Не використовуйте `двигун` для Defold engine, `проект` замість `проєкт`, `додаток` для software application або `сценарій` для Defold script. Для application у документації Defold зазвичай пишіть `застосунок`; форма `програма` доречна, коли йдеться саме про виконувану програму або треба зберегти усталену термінологію зовнішнього продукту. Не змішуйте `відправлення повідомлень` з усталеним поняттям `передавання повідомлень`; для конкретної дії пишіть `надсилання` або `надіслати`.

## Перша згадка понять Defold

Відповідно до загальних правил репозиторію, важливі поняття Defold у першій згадці подавайте українською з англійським терміном у дужках:

* `ігровий об’єкт (game object)`;
* `компонент (component)`;
* `колекція (collection)`;
* `стартова колекція (bootstrap collection)`;
* `проксі колекції (collection proxy)`;
* `фабрика (factory)`;
* `екземпляр (instance)`;
* `на місці (in-place)` і `за посиланням (by reference)`.

Після першої згадки використовуйте українську форму. Повертайтеся до англійської, коли описуєте точний тип ресурсу, елемент інтерфейсу, поле, розширення файлу або інший літерал.

Не додавайте англійський відповідник до кожного повтору й не перевантажуйте ним заголовки. У заголовку його варто залишити лише тоді, коли це допомагає зіставити поняття з інтерфейсом або усталеним технічним терміном.

## Defold, рушій і редактор

Назву `Defold` не перекладайте й не відмінюйте. Будуйте словосполучення так:

* `рушій Defold`;
* `редактор Defold`;
* `проєкт Defold`;
* `у Defold`;
* `за допомогою Defold`.

Розрізняйте редактор і запущену гру. `Сервер редактора` належить процесу редактора, а `сервіс рушія` — налагоджувальному екземпляру рушія. Не називайте обидва просто сервером Defold, якщо відмінність важлива для інструкції.

## Елементи інтерфейсу

У наявному корпусі точні англійські назви інтерфейсу збережено, оскільки саме їх бачить користувач. Не вигадуйте для них українських назв замість літералів.

Зберігайте, зокрема:

* `Outline`, `Console`, `Write Log File`;
* `Add Collection File`, `Add Game Object`, `Add Game Object File`;
* `Add Component`, `Add Component File`;
* `Edit ▸ World Space`, `Edit ▸ Local Space`;
* `Help ▸ Open Editor Server`.

Можна додати пояснення: `вікно Структура (Outline)` або `панель Console`. Для дії в інтерфейсі використовуйте `<kbd>...</kbd>`. У новому тексті позначайте вкладені меню символом `▸`.

Не перекладайте текст усередині `<kbd>` лише тому, що речення довкола нього українське. Виняток — звичайна дія користувача, яка не є точною назвою елемента інтерфейсу, наприклад `<kbd>перетягніть</kbd>`.

## API, код і технічні літерали

Не перекладайте й не змінюйте:

* функції та зворотні виклики: `msg.post()`, `go.get_id()`, `factory.create()`, `init()`, `update()`, `on_message()`;
* повідомлення та значення: `enable`, `disable`, `set_parent`, `collision_response`, `acquire_input_focus`;
* змінні, параметри й поля: `self`, `sender`, `receiver`, `message_id`, `launcherPath`;
* ідентифікатори прикладів: `bean`, `buddy`, `controller`, `team_1`;
* файли, розширення й шляхи: `game.project`, `main.collection`, `.internal/editor.port`, `/openapi.json`;
* команди: `build`, `clean-build`, `build-html5`, `hot-reload`;
* коди стану, виведення консолі, JSON, HTTP-шляхи й рядки помилок.

Згідно із загальними правилами цього репозиторію, не перекладайте блоки коду та коментарі всередині них. Англійський коментар у прикладі коду не є залишком незавершеного перекладу.

Не виправляйте навіть очевидну англійську граматику в рядку коду або очікуваному виведенні, якщо зміна може зробити приклад несумісним з оригіналом. Якщо технічний літерал потребує пояснення, дайте його в українській прозі поруч.

## Markdown і структура файлів

* Зберігайте межі й ключі YAML front matter. Перекладайте значення `title` і `brief`.
* Зберігайте рівні заголовків, структуру списків, таблиць і блоків визначень.
* Перекладайте текст заголовка, але не змінюйте явний якір на кшталт `{#automation-in-defold}`.
* Не змінюйте цілі посилань, URL, шляхи зображень або імена файлів. Перекладайте описовий текст посилання й альтернативний текст зображення.
* Зберігайте директиви включення на кшталт `:[Скорочення](../shared/url-shorthands.md)`: перекладайте підпис, але не шлях.
* Не перекладайте маркери `::: sidenote` і `::: important`; перекладайте лише їхній вміст.
* Використовуйте зворотні лапки для API, файлів, шляхів, команд, полів, повідомлень та інших технічних літералів.
* Не перейменовуйте ресурси, прикладові об’єкти, повідомлення або якірні посилання задля локалізації.

## Правопис і пунктуація

* Використовуйте сучасне написання `проєкт` і похідні: `проєкту`, `проєктний`, `визначений проєктом`.
* У прозі використовуйте апостроф `’` (U+2019): `об’єкт`, `пов’язаний`, `пам’ять`, `ін’єкція`. Не змішуйте його з апострофом U+02BC або ASCII-апострофом `'`.
* Для українських цитат використовуйте лапки `«…»`. Для коду й точних технічних рядків використовуйте зворотні лапки, навіть якщо старий матеріал подає їх у прямих лапках.
* Між частинами речення використовуйте тире `—`, а не дефіс `-`.
* Дефіс зберігайте в складних словах і технічних сполуках: `HTTP-сервер`, `компонент-скрипт`, `ключ-значення`, `батьківсько-дочірній`, `тайм-аут`.
* Природно чергуйте `у`/`в`, `і`/`й`/`та`, не жертвуючи точністю терміна.
* Пишіть `тощо`, а не `і т.д.` у новій прозі.
* Відділяйте комами підрядні частини з `що`, `щоб`, `коли`, `якщо`, `доки`.

## Великі й малі літери

Пишіть з малої літери загальні поняття: `рушій`, `редактор`, `проєкт`, `колекція`, `компонент`, `ігровий об’єкт`, `скрипт`, `повідомлення`.

Зберігайте регістр власних назв, технологій і скорочень: `Defold`, `Defold Foundation`, `Lua`, `JavaScript`, `Python`, `Bob`, `Automation Bridge`, `OpenAPI`, `Protobuf`, `API`, `HTTP`, `URL`, `GUI`, `CLI`, `CI`, `HTML5`, `MCP`, `RAG`, `LLM`, `ШІ`.

Точні елементи інтерфейсу, команди, поля й ідентифікатори завжди зберігають оригінальний регістр.

## Автоматизація й тестування

Новіші українські посібники встановлюють послідовну термінологію для цієї сфери:

* `інспектування, змінення, перевірка й оцінювання` — чотири кроки циклу автоматизації;
* `критерії приймання`, `структурований результат`, `детерміновані докази`;
* `HTTP API редактора`, `API середовища виконання`, `сервіс рушія`;
* `кінцева точка`, `маршрут`, `запит`, `відповідь`, `код статусу`;
* `збирання` для процесу та `збірка` для результату;
* `тест модуля`, `інтеграційний тест`, `наскрізний тест (E2E)`;
* `набір тестів`, `твердження`, `засіб запуску тестів`, `подія завершення`;
* `без графічного інтерфейсу` для `headless`;
* `знімок екрана`, `попередній перегляд сцени`, `область перегляду`, `полотно`.

Офіційні назви та абревіатури на кшталт `Model Context Protocol (MCP)`, `Automation Bridge`, `Continuous Integration (CI)` і `OpenAPI` зберігайте. Українське пояснення додавайте в першій згадці, якщо воно допоможе читачеві.

## Залишки англійської та дефекти старих перекладів

Не сприймайте випадковий англійський текст у старому матеріалі як термінологічне рішення.

Під час роботи з файлом:

* перекладайте залишки звичайної англійської прози, заголовків, підписів і тексту посилань;
* не чіпайте англійську в коді, коментарях коду, ідентифікаторах, точних елементах інтерфейсу, API, шляхах і виведенні;
* виправляйте явні друкарські помилки, відмінки, узгодження, пунктуацію та неправильний апостроф у ділянці, яку редагуєте;
* звіряйте сумнівний термін з `glossary.txt` і його повторюваним уживанням у корпусі;
* не перетворюйте локальне виправлення на повний стилістичний переспів статті без окремої потреби.

Якщо англійська назва може бути і поняттям, і літералом інтерфейсу, залиште літерал та поясніть його українською: `вікно Структура (Outline)`, `властивість Write Log File`, `команда build-html5`.
