## Оптимізація максимальної кількості компонентів {#component-max-count-optimizations}
Файл налаштувань *game.project* містить багато значень, які задають максимальну кількість ресурсів певного типу, що можуть існувати одночасно. Часто цю кількість рахують окремо для кожної завантаженої колекції (collection), яку також називають світом. Рушій Defold використовує ці максимальні значення, щоб заздалегідь виділити пам’ять для відповідної кількості ресурсів і уникнути динамічного виділення та фрагментації пам’яті під час роботи гри.

Структури даних Defold для представлення компонентів (components) та інших ресурсів оптимізовано для мінімального споживання пам’яті. Утім, ці значення слід задавати обачно, щоб не виділяти більше пам’яті, ніж насправді потрібно.

Щоб додатково оптимізувати використання пам’яті, під час збирання Defold аналізує вміст гри й перевизначає максимальні значення, якщо точну кількість можна встановити напевно:

* Якщо колекція не містить компонентів-фабрик (factory components), пам’ять буде виділено для точної кількості компонентів кожного типу та ігрових об’єктів (game objects), а максимальні значення буде проігноровано.
* Якщо колекція містить компонент-фабрику, об’єкти, які він створює, буде проаналізовано. Максимальні значення застосовуватимуться до компонентів, які можуть створювати фабрики, та до ігрових об’єктів.
* Якщо колекція містить фабрику або фабрику колекцій з увімкненою опцією "Dynamic Prototype", вона використовуватиме максимальні значення лічильників.
