## Типи компонентів {#component-types}

Defold підтримує такі типи компонентів (component):

* [Фабрика колекцій (Collection factory)](/manuals/collection-factory) — створення колекцій (collection)
* [Проксі колекції (Collection proxy)](/manuals/collection-proxy) — завантаження та вивантаження колекцій
* [Об’єкт колізій (Collision object)](/manuals/physics) — 2D- і 3D-фізика
* [Камера (Camera)](/manuals/camera) — змінення області перегляду та проєкції ігрового світу
* [Фабрика (Factory)](/manuals/factory) — створення ігрових об’єктів (game object)
* [GUI](/manuals/gui) — рендеринг графічного інтерфейсу користувача
* [Текстова мітка (Label)](/manuals/label) — рендеринг фрагмента тексту
* [Джерело світла (Light)](/manuals/light) — додавання даних про світло для шейдерів
* [Сітка (Mesh)](/manuals/mesh) Відображення 3D-сітки (зі створенням і зміненням під час виконання)
* [Модель (Model)](/manuals/model) Відображення 3D-моделі (з необов’язковими анімаціями)
* [Ефект частинок (Particle FX)](/manuals/particlefx) — створення частинок
* [Скрипт (Script)](/manuals/script) — додавання ігрової логіки
* [Звук (Sound)](/manuals/sound) — відтворення звуку або музики
* [Спрайт (Sprite)](/manuals/sprite) — відображення 2D-зображення (з необов’язковою покадровою анімацією)
* [Карта плиток (Tilemap)](/manuals/tilemap) — відображення сітки плиток

Додаткові компоненти можна додати за допомогою розширень:

* [Модель Rive](/extension-rive) — рендеринг анімації Rive
* [Модель Spine](/extension-spine) — рендеринг анімації Spine


## Увімкнення та вимкнення компонентів {#enabling-and-disabling-components}

Компоненти ігрового об’єкта вмикаються під час його створення. Щоб вимкнути компонент, надішліть йому повідомлення [`disable`](/ref/go/#disable):

```lua
-- disable the component with id 'weapon' on the same game object as this script
msg.post("#weapon", "disable")

-- disable the component with id 'shield' on the 'enemy' game object
msg.post("enemy#shield", "disable")

-- disable all components on the current game object
msg.post(".", "disable")

-- disable all components on the 'enemy' game object
msg.post("enemy", "disable")
```

Щоб знову ввімкнути компонент, надішліть йому повідомлення [`enable`](/ref/go/#enable):

```lua
-- enable the component with id 'weapon'
msg.post("#weapon", "enable")
```

## Властивості компонентів {#component-properties}

Усі типи компонентів Defold мають різні властивості. На [панелі Properties](/manuals/editor/#the-editor-views) редактора відображаються властивості компонента, вибраного на [панелі Outline](/manuals/editor/#the-editor-views). Докладніше про доступні властивості компонентів читайте в посібниках для відповідних типів компонентів.

## Позиція, поворот і масштаб компонента {#component-position-rotation-and-scale}

Візуальні компоненти зазвичай мають властивості позиції та повороту, а найчастіше ще й властивість масштабу. Ці властивості можна змінювати в редакторі, але майже в усіх випадках їх не можна змінювати під час виконання (єдиний виняток — масштаб компонентів спрайта та текстової мітки, який можна змінювати під час виконання).

Якщо потрібно змінити позицію, поворот або масштаб компонента під час виконання, натомість змініть позицію, поворот або масштаб ігрового об’єкта, якому належить цей компонент. Це також вплине на всі інші компоненти цього ігрового об’єкта. Якщо потрібно змінювати лише один із багатьох компонентів, прикріплених до ігрового об’єкта, рекомендовано перенести його в окремий ігровий об’єкт і додати цей об’єкт як дочірній до ігрового об’єкта, якому компонент належав спочатку.

## Порядок відображення компонентів {#component-draw-order}

Порядок відображення візуальних компонентів залежить від двох чинників:

### Предикати скрипта рендерингу {#render-script-predicates}
Кожному компоненту призначено [матеріал](/manuals/material/), а кожен матеріал має один або кілька тегів. Скрипт рендерингу, своєю чергою, визначає низку предикатів, кожен із яких відповідає одному або кільком тегам матеріалу. У функції *update()* скрипта рендерингу [предикати відображаються один за одним](/manuals/render/#render-predicates), і для кожного предиката відображаються компоненти, що відповідають визначеним у ньому тегам. Стандартний скрипт рендерингу спочатку відображає спрайти та карти плиток за один прохід, а потім ефекти частинок за інший прохід, в обох випадках у світовому просторі. Далі скрипт рендерингу відображає компоненти GUI за окремий прохід в екранному просторі.

### Значення z компонента {#component-z-value}
Усі ігрові об’єкти та компоненти розташовані в 3D-просторі, а їхні позиції задано об’єктами `vector3`. Коли ви переглядаєте графіку гри у 2D, значення X та Y визначають позицію об’єкта вздовж осей «ширини» та «висоти», а позиція Z визначає позицію вздовж осі «глибини». Позиція Z дає змогу керувати видимістю об’єктів, що перекриваються: спрайт зі значенням Z, рівним 1, відображатиметься перед спрайтом із позицією Z, рівною 0. За замовчуванням Defold використовує систему координат, у якій значення Z можуть бути від -1 до 1:

![модель](images/graphics/z-order.png)

Компоненти, що відповідають [предикату рендерингу](/manuals/render/#render-predicates), відображаються разом, а порядок їх відображення залежить від підсумкового значення z компонента. Підсумкове значення z компонента — це сума значень z самого компонента, ігрового об’єкта, якому він належить, і всіх батьківських ігрових об’єктів.

::: sidenote
Порядок відображення кількох компонентів GUI **не** визначається їхнім значенням z. Порядком відображення компонентів GUI керує функція [gui.set_render_order()](/ref/gui/#gui.set_render_order:order).
:::

Приклад: два ігрові об’єкти A та B. B — дочірній об’єкт A. B має компонент спрайта.

| Об’єкт   | Значення Z |
|----------|---------|
| A        | 2       |
| B        | 1       |
| B#sprite | 0.5     |

![](images/graphics/component-hierarchy.png)

У наведеній вище ієрархії підсумкове значення z компонента спрайта в B становить 2 + 1 + 0.5 = 3.5.

::: important
Якщо два компоненти мають однакове значення z, порядок не визначений. Через це компоненти можуть мерехтіти, міняючись місцями, або відображатися в одному порядку на одній платформі та в іншому — на іншій.

Скрипт рендерингу визначає ближню та дальню площини для значень z. Компоненти, значення z яких виходять за межі цього діапазону, не відображатимуться. За замовчуванням діапазон становить від -1 до 1, але [його легко змінити](/manuals/render/#default-view-projection). Числова точність значень Z за ближньої та дальньої меж -1 і 1 дуже висока. Під час роботи з 3D-ресурсами вам може знадобитися змінити ближню та дальню межі стандартної проєкції у власному скрипті рендерингу. Докладніше читайте в [посібнику з рендерингу](/manuals/render/).
:::
