# Ігнорування файлів {#ignoring-files}

Редактор та інструменти Defold можна налаштувати так, щоб вони ігнорували файли й папки в проєкті. Це може бути корисно, якщо проєкт містить файли з розширеннями, які конфліктують із розширеннями, що використовуються в Defold. Один із таких прикладів — файли мовою Go з розширенням `.go`, яке редактор також використовує для файлів ігрових об’єктів (game object).

## Файл `.defignore` {#the-defignore-file}
Файли й папки, які потрібно виключити, визначаються у файлі `.defignore` у кореневому каталозі проєкту. У цьому файлі слід перелічити файли й папки для виключення, по одному на рядок. Приклад:

```
/path/to/file.png
/otherpath
```

Це виключить файл `/path/to/file.png` і все за шляхом `/otherpath`.

## Файл `.defunload` {#the-defunload-file}

У деяких великих проєктах, які містять кілька незалежних модулів, може знадобитися виключити частини проєкту із завантаження, щоб зменшити використання пам’яті й час завантаження в редакторі. Для цього можна перелічити шляхи, які потрібно виключити із завантаження, у файлі `.defunload` у каталозі проєкту.

Простіше кажучи, файл `.defunload` дає змогу приховати частини проєкту від редактора так, щоб посилання на приховані ресурси не спричиняли помилку збирання.

Шаблони в `.defunload` використовують ті самі правила, що й файл `.defignore`. Незавантажені колекції (collection) та ігрові об’єкти поводитимуться як порожні, коли на них посилаються завантажені ресурси. Інші ресурси, що відповідають шаблонам `.defunload`, перебуватимуть у незавантаженому стані, і їх не можна буде переглядати в редакторі. Однак якщо завантажений ресурс залежить від них, незавантажені ресурси та їхні залежності завантажуються автоматично.

Наприклад, якщо Sprite залежить від зображень в Atlas, доведеться завантажити Atlas, інакше відсутнє зображення буде позначено як помилку. Якщо це станеться, сповіщення попередить користувача про ситуацію й повідомить, на який незавантажений ресурс і звідки посилаються.

Редактор не дозволить користувачеві додавати посилання на ресурси `.defunloaded` із завантажених ресурсів, тому така ситуація виникає лише під час читання ресурсів із диска.

На відміну від файлу `.defignore`, після редагування файлу `.defunload` потрібно перезапустити редактор, щоб зміни набули чинності.
