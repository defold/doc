# Χρήση πρακτόρων προγραμματισμού AI με το Defold {#using-ai-coding-agents-with-defold}

Οι πράκτορες προγραμματισμού που αξιοποιούν LLM και πολυτροπικά μοντέλα μπορούν να επιθεωρούν, να τροποποιούν και να επαληθεύουν έργα Defold, καλώντας τις ίδιες ανεξάρτητες από το μοντέλο διεπαφές που χρησιμοποιούν οι προγραμματιστές, τα τοπικά σενάρια, οι ενσωματώσεις IDE και το CI. Μπορείτε να χρησιμοποιήσετε έναν πράκτορα όταν η εργασία απαιτεί διερεύνηση και προσαρμογή.

Το Defold δεν εξαρτάται από συγκεκριμένο πάροχο μοντέλου ή πρωτόκολλο πρακτόρων. Τα έργα Defold λειτουργούν καλά είτε με το Claude Code, το Codex, το Cursor είτε με οποιαδήποτε άλλη λύση. Ένα περιβάλλον πράκτορα χρειάζεται μόνο τις συγκεκριμένες δυνατότητες που παραχωρούνται για την εργασία, όπως ανάγνωση αρχείων έργου, εκτέλεση επιλεγμένων εντολών, κλήση τοπικών λειτουργιών HTTP, ανάλυση JSON ή επιθεώρηση εικόνων. Αυτό είναι δυνατό χάρη στις εκτεθειμένες διεπαφές αυτοματισμού του Defold για τον επεξεργαστή και για μια μηχανή παιχνιδιού που εκτελείται, καθώς και επειδή τα αρχεία έργου του Defold είναι πόροι βασισμένοι σε κείμενο που αναλύονται εύκολα.

## Πότε είναι χρήσιμος ένας πράκτορας AI {#when-an-ai-agent-is-useful}

Ένας πράκτορας μπορεί να είναι χρήσιμος όταν μια εργασία απαιτεί, για παράδειγμα:

* εύρεση σχετικών πόρων και τεκμηρίωσης,
* επιλογή μεταξύ πιθανών υλοποιήσεων,
* αλλαγή πολλών σχετιζόμενων αρχείων,
* ερμηνεία αποτυχιών δημιουργίας ή δοκιμών,
* σύγκριση ενός οπτικού αποτελέσματος με σημασιολογικά κριτήρια αποδοχής,
* εκτέλεση μιας οριοθετημένης προσπάθειας επιδιόρθωσης βάσει των αποδεικτικών στοιχείων που συλλέχθηκαν.

Οι πράκτορες είναι ισχυροί σε μη ντετερμινιστικές διαδικασίες ανάπτυξης, διερεύνησης και δοκιμών. Μπορούν να βοηθήσουν στη δημιουργία ποικίλων λύσεων και συνεργάζονται πολύ καλά με το Defold.

## Ανεξάρτητες από το μοντέλο διεπαφές του Defold {#model-neutral-defold-interfaces}

Το Defold προσφέρει αρκετές υποστηριζόμενες διεπαφές που απαιτούνται για την εκτέλεση της εργασίας με οποιοδήποτε διαθέσιμο μοντέλο:

* Τα αρχεία έργου και τα εργαλεία κελύφους επιτρέπουν άμεση επιθεώρηση και αλλαγές κειμένου.
* Τα [Σενάρια επεξεργαστή](/manuals/editor-scripts) μπορούν να παρέχουν λειτουργίες και εργαλεία για πόρους συγκεκριμένα για κάθε έργο.
* Το [Editor HTTP API](/manuals/editor-http-api) παρέχει εντολές επεξεργαστή, αποτελέσματα δημιουργίας, έξοδο κονσόλας, αναζήτηση αναφορών, προεπισκοπήσεις, προτιμήσεις και διαδρομές σεναρίων επεξεργαστή.
* Η [υπηρεσία μηχανής και τα API αυτοματισμού χρόνου εκτέλεσης](/manuals/engine-service) παρέχουν ζωντανή κατάσταση της δοκιμαστικής μηχανής, είσοδο, στιγμιότυπα οθόνης και λειτουργίες που ορίζονται από επεκτάσεις.
* Το [Bob](/manuals/bob) παρέχει δημιουργίες από τη γραμμή εντολών, αναφορές, αρχεία και πακέτα.

Ένα μοντέλο που είναι διαθέσιμο μόνο μέσω διεπαφής συνομιλίας μπορεί να προτείνει αλλαγές κώδικα, αλλά δεν μπορεί να επιθεωρήσει ανεξάρτητα το τοπικό έργο ή να επαληθεύσει ένα εκτελούμενο αποτέλεσμα. Η πρόσθετη περιβάλλουσα ενσωμάτωση καθορίζει τι μπορεί πράγματι να παρατηρήσει και να κάνει ο πράκτορας.

## Επίπεδα ενσωμάτωσης {#integration-layers}

Μπορεί να δημιουργηθεί ένα επίπεδο ενσωμάτωσης για τη σύνδεση ενός πράκτορα με τοπικές λειτουργίες του Defold. Μπορεί να είναι ένα wrapper για το κέλυφος, ένα πρόγραμμα γραμμής εντολών, μια επέκταση IDE, ένας πελάτης OpenAPI, ένας ελεγκτής δοκιμών ή ένας προσαρμογέας πρωτοκόλλου.

Διατηρήστε την πολιτική και τα διαπιστευτήρια σε αυτό το τοπικό επίπεδο. Κάθε λειτουργία που επιφέρει αλλαγές θα πρέπει να επιστρέφει δομημένα αποτελέσματα ή να οδηγεί σε ένα ντετερμινιστικό βήμα επαλήθευσης.

Για λειτουργίες του επεξεργαστή, εντοπίστε την τρέχουσα διεπαφή μέσω του `/openapi.json`, αντί να παρέχετε στον πράκτορα ένα μόνιμα κωδικοποιημένο αντίγραφο ενός API. Για επεκτάσεις χρόνου εκτέλεσης, ελέγξτε την εύρυθμη λειτουργία, την έκδοση API και τις δυνατότητές τους.

Μπορεί να είναι πρακτικό να διαχωρίζετε τα εργαλεία ανά επίπεδο προνομίων:

| Επίπεδο | Παραδείγματα |
| ------------ | ----------------------------------------------------- |
| Μόνο για ανάγνωση | Επιθεώρηση έργου, OpenAPI, `/ref`, κονσόλα, προεπισκόπηση |
| Επαλήθευση | Μεταγλώττιση, δοκιμές, δημιουργίες HTML5, συγκρίσεις εικόνων |
| Τροποποίηση | Αλλαγές αρχείων, συναλλαγές πόρων |
| Προνομιακό | `/eval`, εξωτερικές εντολές, αλλαγές εξαρτήσεων |

Διατηρώντας τον προσαρμογέα ξεχωριστό από τη μηχανή και τον επεξεργαστή, οι υποστηριζόμενες διεπαφές του Defold παραμένουν ανεξάρτητες από πάροχο μοντέλου ή πρωτόκολλο πρακτόρων. Ένας προσαρμογέας μπορεί να εκθέτει μόνο τις λειτουργίες που είναι κατάλληλες για το περιβάλλον του, ενώ οι πολιτικές αδειών και επιβεβαίωσης παραμένουν στην εφαρμογή που φιλοξενεί τον πράκτορα.

### Model Context Protocol {#model-context-protocol}

Το [Model Context Protocol](https://modelcontextprotocol.io/) (MCP) είναι ένας προαιρετικός προσαρμογέας μεταξύ ενός πράκτορα και ενός επιπέδου ενσωμάτωσης. Ένας διακομιστής MCP μπορεί να εκθέτει λειτουργίες του Defold ως εργαλεία και επιλεγμένη τεκμηρίωση ως πόρους.

::: important
Μην παρέχετε σε κάθε μοντέλο απεριόριστη πρόσβαση στο κέλυφος και στο `/eval`.
:::

Το Defold δεν απαιτεί επί του παρόντος διακομιστή MCP, επειδή οι βασικές δυνατότητες αυτοματισμού εκτίθενται ήδη μέσω ανοικτών διεπαφών γενικού σκοπού. Ο επεξεργαστής παρέχει ένα τοπικό HTTP API με προδιαγραφή OpenAPI. Οι σύγχρονοι πράκτορες μπορούν να καλούν αυτές τις διεπαφές απευθείας ή να δημιουργούν τους δικούς τους προσαρμογείς.

Επομένως, ένα επίσημο MCP θα αναπαρήγαγε σε μεγάλο βαθμό την υπάρχουσα επιφάνεια API και θα δημιουργούσε ένα ακόμη επίπεδο ενσωμάτωσης που θα έπρεπε να συντηρεί το Defold. Μια καλύτερη μακροπρόθεσμη στρατηγική είναι να παραμένουν τα υποκείμενα API αυτοματισμού HTTP και χρόνου εκτέλεσης σταθερά, ανιχνεύσιμα και καλά τεκμηριωμένα, επιτρέποντας παράλληλα στην κοινότητα ή σε μεμονωμένους παρόχους εργαλείων να δημιουργούν ελαφριά wrapper MCP όταν χρειάζεται.

Αντί γι' αυτό, παρέχουμε μια επίσημη επέκταση [Automation Bridge](https://github.com/defold/extension-automation-bridge), ώστε ένα παιχνίδι που εκτελείται να μπορεί να ελέγχεται μέσω μιας υπηρεσίας από την πλευρά της μηχανής.

### Ενσωματώσεις MCP της κοινότητας {#community-mcp-integrations}

Οι ενσωματώσεις MCP που έχουν δημιουργηθεί από την κοινότητα περιλαμβάνουν:

* το [έργο Defold MCP του Fulviuus](https://github.com/Fulviuus/defold-mcp),
* το [έργο Defold MCP του ChadAragorn](https://github.com/ChadAragorn/defold-mcp).

Αυτά τα έργα δεν αναπτύσσονται, δεν ελέγχονται, δεν συντηρούνται και δεν υποστηρίζονται επίσημα από το Ίδρυμα Defold. Πριν εγκαταστήσετε οποιαδήποτε ενσωμάτωση της κοινότητας, επιθεωρήστε τον τρέχοντα πηγαίο κώδικα, τις εξαρτήσεις, τις άδειες, τη συμπεριφορά δικτύου και τη συμβατότητά της με την έκδοση Defold που χρησιμοποιείτε.

## Οδηγίες έργου {#project-instructions}

Τα διαθέσιμα μεγάλα γλωσσικά μοντέλα που χρησιμοποιούνται σε ροές εργασίας με πράκτορες αποδίδουν γενικά καλύτερα με καλές οδηγίες. Γι' αυτό, συχνά προστίθενται στα έργα αρχεία Markdown πρακτόρων που περιγράφουν την επιθυμητή συμπεριφορά τους ή δεξιότητες. Για καλύτερα αποτελέσματα, καλό είναι να σχεδιάζετε και να γράφετε τις δικές σας οδηγίες ξεχωριστά για κάθε έργο, αν και ορισμένες κοινές γνώσεις και κανόνες μπορούν να επαναχρησιμοποιούνται.

Ένα πρώτο αρχείο που πολλοί πράκτορες αναζητούν και διαβάζουν είναι ένα κανονικό αρχείο όπως το `AGENTS.md`, το οποίο μπορεί να περιγράφει:

* τη δομή του έργου και τα σημαντικά σημεία εισόδου,
* τις συμβάσεις μορφοποίησης και ονομασίας,
* τις εντολές για δημιουργίες, δοκιμές και επικύρωση,
* τα απαιτούμενα συμβάντα ολοκλήρωσης και τις θέσεις των παραδοτέων,
* τα αρχεία ή τους καταλόγους που δεν πρέπει να αλλάξουν,
* τις λειτουργίες που απαιτούν έγκριση,
* τις παραδοχές για την πλατφόρμα και τους γνωστούς περιορισμούς.

Ορισμένες λύσεις μπορεί να βασίζονται σε ξεχωριστά αρχεία Markdown για συγκεκριμένες ενέργειες ή στις λεγόμενες «δεξιότητες».

Ένα παράδειγμα οδηγιών και δεξιοτήτων προσανατολισμένων στο Defold από την κοινότητα είναι διαθέσιμο [εδώ στο φόρουμ του Defold](https://forum.defold.com/t/agent-config-collection-of-agents-md-and-skills/82387).

Συνιστούμε να διατηρείτε τις οδηγίες σας σε αρχεία όπως το `AGENTS.md` και τους ορισμούς δεξιοτήτων σύντομους, περιεκτικούς, εύκολους στον έλεγχο και στη συντήρηση, καθώς και ενημερωμένους. Οι οδηγίες που αφορούν συγκεκριμένα ένα έργο μπορούν να αποθηκεύονται στον έλεγχο εκδόσεων, καθιστώντας τις αλλαγές ανιχνεύσιμες και βοηθώντας στη βελτίωση της απόδοσης της ροής εργασίας με την πάροδο του χρόνου.

Αξίζει επίσης να δοκιμάζετε τακτικά την απόδοση των πιο πρόσφατων μοντέλων χωρίς αυτές τις οδηγίες. Τα νεότερα μοντέλα συχνά δεν χρειάζονται πλέον καθοδήγηση που ήταν παλαιότερα απαραίτητη, ενώ παρωχημένες δεξιότητες ή υπερβολικά αυστηρές οδηγίες μπορούν μερικές φορές να μειώσουν την απόδοση.

Αποφύγετε τη δημιουργία σύνθετων τεχνικών δεξιοτήτων που απαιτούν σημαντική μακροπρόθεσμη συντήρηση. Αντί γι' αυτό, επικεντρωθείτε στην ανάπτυξη εργαλείων και ροών εργασίας που παραμένουν πολύτιμα ανεξάρτητα από το πόσο βελτιώνονται τα υποκείμενα μοντέλα.

## Εντοπισμός τεκμηρίωσης {#documentation-discovery}

Οι πράκτορες αποδίδουν καλύτερα με ακριβή και ενημερωμένη τεκμηρίωση. Συγκεντρώστε τρέχουσες πληροφορίες από:

* Το `/openapi.json` περιγράφει το τρέχον HTTP API του επεξεργαστή.
* Το `/ref` αναζητά την τεκμηρίωση API που περιλαμβάνεται στον επεξεργαστή που εκτελείται, όταν αυτή η λειτουργία είναι διαθέσιμη.
* Το [ευρετήριο τεκμηρίωσης LLM](https://defold.com/llms.txt) περιέχει συνδέσμους προς επίσημα εγχειρίδια, χώρους ονομάτων API και παραδείγματα.
* Η [πλήρης τεκμηρίωση LLM](https://defold.com/llms-full.txt) υποστηρίζει αναζήτηση εκτός σύνδεσης και τοπική ευρετηρίαση.

Ανακτήστε μόνο τις σελίδες που σχετίζονται με την εργασία. Συνιστάται να χρησιμοποιείτε το πλήρες συνδυασμένο έγγραφο μόνο για ευρετηρίαση εκτός σύνδεσης ή για [Retrieval-Augmented Generation (RAG)](https://en.wikipedia.org/wiki/Retrieval-augmented_generation). Και πάλι, το πλήρες αρχείο δεν θα πρέπει κανονικά να περιλαμβάνεται σε κάθε αίτημα προς το μοντέλο, ώστε να εξοικονομούνται διακριτικά και να μην επιβαρύνεται το περιβάλλον με περιττές πληροφορίες.

## Οριοθετημένοι βρόχοι αλλαγών και επαλήθευσης {#bounded-change-and-verification-loops}

Οι πράκτορες θα πρέπει να ακολουθούν τον ίδιο [βρόχο επιθεώρησης, αλλαγής, επαλήθευσης και αξιολόγησης](/manuals/automation/#the-automation-loop) όπως κάθε άλλος αυτοματισμός.

Πριν αλλάξετε αρχεία, καλό είναι να καθορίσετε τα κριτήρια αποδοχής και, προαιρετικά, επίσης:
* τα επιτρεπόμενα αρχεία και τις λειτουργίες,
* τις εντολές δημιουργίας και δοκιμών,
* τα απαιτούμενα αρχεία καταγραφής, τις αναφορές, την κατάσταση ή τις εικόνες,
* ένα χρονικό όριο για κάθε ασύγχρονο βήμα,
* έναν μέγιστο αριθμό προσπαθειών επιδιόρθωσης.

Ένας πράκτορας μπορεί να διαγνώσει και να επιδιορθώσει μια ντετερμινιστική αποτυχία CI, αλλά το ίδιο το στάδιο CI θα πρέπει να παραμένει αναπαραγώγιμο χωρίς τον πράκτορα.

Καλές πρακτικές για αυτοματοποιημένες δοκιμές και επαλήθευση περιγράφονται σε [αυτό το εγχειρίδιο](/manuals/automated-testing).

## Πολυτροπική αξιολόγηση {#multimodal-evaluation}

Ένας πράκτορας με δυνατότητα εισόδου εικόνας μπορεί να επιθεωρεί [προεπισκοπήσεις του επεξεργαστή](/manuals/editor-http-api/#rendering-scene-previews), στιγμιότυπα οθόνης κατά τον χρόνο εκτέλεσης, οπτικές διαφορές και καταγραφές προγράμματος περιήγησης.

Χρησιμοποιήστε πολυτροπική αξιολόγηση για σημασιολογικά ζητήματα, όπως αποκομμένες ετικέτες, επικαλυπτόμενα στοιχεία ελέγχου, ασαφείς καταστάσεις επιλογής, σύνθεση ή περιεχόμενο εκτός μιας ασφαλούς περιοχής. Καθορίστε εκ των προτέρων την αναμενόμενη περιοχή προβολής και τα κριτήρια.

Διαβάστε περισσότερα για τις προεπισκοπήσεις του επεξεργαστή, τα στιγμιότυπα οθόνης κατά τον χρόνο εκτέλεσης και την οπτική επιθεώρηση σε [αυτό το εγχειρίδιο](/manuals/automated-testing).

## Ασφάλεια, απομόνωση και καλές πρακτικές {#security-isolation-and-good-practices}

* Αντιμετωπίστε τον διακομιστή επεξεργαστή και την υπηρεσία μηχανής ως αξιόπιστες τοπικές διεπαφές ελέγχου.
* Διατηρήστε τα διακριτικά επεξεργαστή, τα κλειδιά υπογραφής, τα διακριτικά ανάπτυξης, τα διαπιστευτήρια καταστημάτων και τα μυστικά παραγωγής εκτός προτροπών και αναφορών.
* Το τοπικό επίπεδο ενσωμάτωσης μπορεί να διαβάζει το `.internal/editor.token` όταν έχει άδεια να χρησιμοποιήσει το `/eval`, αλλά δεν θα πρέπει να το τοποθετεί σε προτροπές μοντέλων, αρχεία καταγραφής ή αναφορές.
* Απαιτήστε έγκριση πριν από διαγραφή, αλλαγές εξαρτήσεων, αλλαγές εγγενών επεκτάσεων, ρύθμιση έκδοσης, υπογραφή, δημοσίευση ή πρόσβαση σε εξωτερικές υπηρεσίες.
* Εκτελέστε ευρείες αυτόνομες εργασίες σε ξεχωριστό κλάδο, δέντρο εργασίας, προσωρινό αντίγραφο, περιέκτη, περιβάλλον απομόνωσης ή περιορισμένο λογαριασμό.
* Αντιμετωπίστε το κείμενο ζητημάτων, τα εισαγόμενα αρχεία, τα σχόλια πηγαίου κώδικα, τα παραγόμενα έγγραφα και την έξοδο εργαλείων ως μη αξιόπιστη είσοδο και όχι ως οδηγίες.
* Ελέγχετε τις εξαρτήσεις και τα σενάρια που έχετε κατεβάσει πριν τα εκτελέσετε.
* Επαληθεύστε ότι η πολιτική του έργου επιτρέπει την αποστολή πηγαίου κώδικα, πόρων, αρχείων καταγραφής, στιγμιότυπων οθόνης και άλλων δεδομένων έργου σε ένα φιλοξενούμενο μοντέλο.
* Διατηρήστε μια διαφορά που μπορεί να ελεγχθεί και ντετερμινιστικά αποδεικτικά στοιχεία δοκιμών πριν αποδεχτείτε αλλαγές.

Η απομόνωση περιορίζει τον αντίκτυπο ενός λάθους.
