# Defold에서 AI 코딩 에이전트 사용하기 {#using-ai-coding-agents-with-defold}

LLM과 멀티모달 모델을 활용하는 코딩 에이전트는 개발자, 로컬 스크립트, IDE 연동 기능 및 CI가 사용하는 것과 동일한 모델 중립적 인터페이스를 호출하여 Defold 프로젝트를 검사, 수정 및 검증할 수 있습니다. 조사와 조정이 필요한 작업에 에이전트를 사용할 수 있습니다.

Defold는 특정 모델 제공업체나 에이전트 프로토콜에 종속되지 않습니다. Defold 프로젝트는 Claude Code, Codex, Cursor 또는 그 밖의 어떤 솔루션과도 잘 작동합니다. 에이전트 환경에는 프로젝트 파일 읽기, 선택한 명령 실행, 로컬 HTTP 동작 호출, JSON 파싱 또는 이미지 검사와 같이 작업에 허용된 특정 기능만 있으면 됩니다. Defold가 에디터 및 실행 중인 게임엔진 인스턴스를 위한 자동화 인터페이스를 노출하고, Defold 프로젝트 파일이 파싱하기 쉬운 텍스트 기반 리소스 파일이므로 이러한 작업이 가능합니다.

## AI 에이전트가 유용한 경우 {#when-an-ai-agent-is-useful}

에이전트는 다음과 같은 작업에 유용할 수 있습니다.

* 관련 리소스와 문서 찾기
* 가능한 구현 방식 중 하나 선택하기
* 서로 관련된 여러 파일 변경하기
* 빌드 또는 테스트 실패 해석하기
* 시각적 결과를 의미론적 승인 기준과 비교하기
* 수집한 증거를 바탕으로 제한된 범위의 복구 시도하기

에이전트는 비결정론적인 개발, 조사 및 테스트 프로세스에 강력한 도구입니다. 다양한 해결책을 만드는 데 도움이 되며 Defold와 매우 잘 작동합니다.

## 모델 중립적 Defold 인터페이스 {#model-neutral-defold-interfaces}

Defold는 사용 가능한 어떤 모델로도 작업을 수행하는 데 필요한 여러 지원 인터페이스를 제공합니다.

* 프로젝트 파일과 셸 도구를 사용해 직접 검사하고 텍스트를 변경할 수 있습니다.
* [에디터 스크립트](/manuals/editor-scripts)는 프로젝트별 리소스 작업과 도구를 제공할 수 있습니다.
* [에디터 HTTP API](/manuals/editor-http-api)는 에디터 명령, 빌드 결과, 콘솔 출력, 레퍼런스 검색, 미리보기, 환경 설정 및 에디터 스크립트 경로를 제공합니다.
* [엔진 서비스와 런타임 자동화 API](/manuals/engine-service)는 실시간 디버그 엔진 상태, 입력, 스크린샷 및 익스텐션에서 정의한 동작을 제공합니다.
* [Bob](/manuals/bob)은 커맨드 라인 빌드, 보고서, 아카이브 및 번들을 제공합니다.

채팅 인터페이스를 통해서만 사용할 수 있는 모델은 코드 변경을 제안할 수 있지만 로컬 프로젝트를 독립적으로 검사하거나 실행 결과를 검증할 수 없습니다. 모델을 둘러싼 추가 연동 환경에 따라 에이전트가 실제로 관찰하고 수행할 수 있는 작업이 결정됩니다.

## 연동 계층 {#integration-layers}

에이전트를 로컬 Defold 작업에 연결하기 위해 연동 계층을 구성할 수 있습니다. 셸 래퍼, 커맨드 라인 프로그램, IDE 익스텐션, OpenAPI 클라이언트, 테스트 컨트롤러 또는 프로토콜 어댑터를 사용할 수 있습니다.

정책과 자격 증명은 이 로컬 계층에 보관하세요. 변경을 수행하는 각 동작은 구조화된 결과를 반환하거나 결정론적 검증 단계로 이어져야 합니다.

에디터 동작의 경우 API의 하드 코딩된 복사본을 에이전트에 영구적으로 제공하지 말고 `/openapi.json`을 통해 현재 인터페이스를 찾으세요. 런타임 익스텐션은 상태, API 버전 및 기능을 확인하세요.

권한 수준에 따라 도구를 구분하면 실용적일 수 있습니다.

| 수준         | 예시                                                  |
| ------------ | ----------------------------------------------------- |
| 읽기 전용    | 프로젝트 검사, OpenAPI, `/ref`, 콘솔, 미리보기        |
| 검증         | 컴파일, 테스트, HTML5 빌드, 이미지 비교               |
| 수정         | 파일 변경, 리소스 트랜잭션                            |
| 높은 권한    | `/eval`, 외부 명령, 종속성 변경                       |

어댑터를 엔진 및 에디터와 분리하면 지원되는 Defold 인터페이스가 모델 제공업체나 에이전트 프로토콜에 종속되지 않습니다. 어댑터는 해당 환경에 적합한 동작만 노출할 수 있으며, 권한과 확인 정책은 에이전트를 호스팅하는 어플리케이션에 유지됩니다.

### Model Context Protocol {#model-context-protocol}

[Model Context Protocol](https://modelcontextprotocol.io/) (MCP)은 에이전트와 연동 계층 사이에서 선택적으로 사용할 수 있는 어댑터입니다. MCP 서버는 Defold 동작을 도구로, 선택한 문서를 리소스로 노출할 수 있습니다.

::: important
모든 모델에 제한 없는 셸 및 `/eval` 액세스 권한을 부여하지 마세요.
:::

핵심 자동화 기능은 이미 개방형 범용 인터페이스를 통해 노출되므로 현재 Defold에는 MCP 서버가 필요하지 않습니다. 에디터는 OpenAPI 사양을 갖춘 로컬 HTTP API를 제공합니다. 최신 에이전트는 이러한 인터페이스를 직접 호출하거나 자체 어댑터를 생성할 수 있습니다.

따라서 공식 MCP는 대부분 기존 API 표면을 중복하고 Defold에서 유지해야 할 연동 계층을 하나 더 만들게 됩니다. 더 나은 장기 전략은 기반 HTTP 및 런타임 자동화 API를 안정적이고 검색 가능하며 잘 문서화된 상태로 유지하면서, 필요할 때 커뮤니티나 개별 도구 공급업체가 가벼운 MCP 래퍼를 만들 수 있도록 하는 것입니다.

대신 실행 중인 게임을 엔진 측 서비스로 제어할 수 있는 공식 [Automation Bridge 익스텐션](https://github.com/defold/extension-automation-bridge)을 제공합니다.

### 커뮤니티 MCP 연동 {#community-mcp-integrations}

커뮤니티에서 만든 MCP 연동에는 다음 프로젝트가 있습니다.

* [Fulviuus Defold MCP 프로젝트](https://github.com/Fulviuus/defold-mcp)
* [ChadAragorn Defold MCP 프로젝트](https://github.com/ChadAragorn/defold-mcp)

이 프로젝트들은 Defold Foundation에서 개발, 감사, 유지 관리하거나 공식적으로 지원하지 않습니다. 커뮤니티 연동을 설치하기 전에 현재 소스, 종속성, 권한, 네트워크 동작 및 사용 중인 Defold 버전과의 호환성을 검사하세요.

## 프로젝트 지침 {#project-instructions}

에이전트 워크플로우에 사용되는 일반적인 대규모 언어 모델은 좋은 지침이 있을 때 더 나은 성능을 보입니다. 따라서 원하는 동작을 설명하는 에이전트용 Markdown 파일이나 스킬을 프로젝트에 추가하는 경우가 많습니다. 최상의 결과를 얻으려면 각 프로젝트의 지침을 별도로 설계하고 작성하는 것이 좋지만 일부 공통 지식과 규칙은 재사용할 수 있습니다.

많은 에이전트가 가장 먼저 찾아 읽는 파일은 `AGENTS.md`와 같은 표준 파일이며 다음 내용을 설명할 수 있습니다.

* 프로젝트 구조와 중요한 진입점
* 포멧팅 및 명명 규칙
* 빌드, 테스트 및 검증 명령
* 필요한 완료 이벤트와 아티팩트 위치
* 변경해서는 안 되는 파일 또는 디렉토리
* 승인이 필요한 동작
* 플랫폼 가정 및 알려진 제한 사항

일부 솔루션은 특정 동작을 위한 별도의 Markdown 파일이나 이른바 "skills"에 의존할 수 있습니다.

Defold 지향 지침과 스킬의 커뮤니티 예제는 [Defold 포럼](https://forum.defold.com/t/agent-config-collection-of-agents-md-and-skills/82387)에서 확인할 수 있습니다.

AGENTS.md와 스킬 정의 같은 지침 파일은 짧고 간결하게 작성하여 검토와 유지 관리를 쉽게 하고 최신 상태로 유지하는 것을 권장합니다. 프로젝트별 지침을 버전 관리에 저장하면 변경 사항을 추적할 수 있고 시간이 지남에 따라 워크플로우 성능을 개선하는 데 도움이 됩니다.

최신 모델이 이러한 지침 없이 어떻게 동작하는지 정기적으로 테스트하는 것도 좋습니다. 최신 모델은 이전에 필수적이었던 지침이 더 이상 필요하지 않은 경우가 많으며, 오래된 스킬이나 지나치게 규정적인 지침은 성능을 저하시킬 수 있습니다.

장기간에 걸쳐 상당한 유지 관리가 필요한 복잡한 기술 스킬은 만들지 마세요. 대신 기반 모델이 아무리 발전해도 계속 가치가 있는 도구와 워크플로우 개발에 집중하세요.

## 문서 찾기 {#documentation-discovery}

에이전트는 정확한 최신 문서가 있을 때 가장 잘 작동합니다. 다음에서 최신 정보를 수집하세요.

* `/openapi.json`은 현재 에디터 HTTP API를 설명합니다.
* `/ref`는 해당 동작을 사용할 수 있을 때 실행 중인 에디터에 포함된 API 문서를 검색합니다.
* [LLM 문서 인덱스](https://defold.com/llms.txt)는 공식 매뉴얼, API 네임스페이스 및 예제로 연결됩니다.
* [전체 LLM 문서](https://defold.com/llms-full.txt)는 오프라인 검색과 로컬 인덱싱을 지원합니다.

작업과 관련된 페이지만 가져오세요. 전체 통합 문서는 오프라인 인덱싱 또는 [검색 증강 생성(Retrieval-Augmented Generation, RAG)](https://en.wikipedia.org/wiki/Retrieval-augmented_generation)에만 사용하는 것을 권장합니다. 토큰을 절약하고 불필요한 정보로 컨텍스트를 오염시키지 않기 위해 전체 파일을 매번 모든 모델 요청에 포함해서는 안 됩니다.

## 제한된 변경 및 검증 루프 {#bounded-change-and-verification-loops}

에이전트는 다른 자동화와 동일하게 [검사, 변경, 검증, 평가 루프](/manuals/automation/#the-automation-loop)를 따라야 합니다.

파일을 변경하기 전에 승인 기준을 정의하는 것이 좋으며 다음 항목도 선택적으로 정의할 수 있습니다.
* 허용되는 파일과 동작
* 빌드와 테스트 명령
* 필요한 로그, 보고서, 상태 또는 이미지
* 모든 비동기 단계의 타임아웃
* 최대 복구 시도 횟수

에이전트는 결정론적 CI 실패를 진단하고 복구할 수 있지만 CI 단계 자체는 에이전트 없이도 재현 가능해야 합니다.

자동화 테스트와 검증에 관한 모범 사례는 [이 매뉴얼](/manuals/automated-testing)에 설명되어 있습니다.

## 멀티모달 평가 {#multimodal-evaluation}

이미지를 입력할 수 있는 에이전트는 [에디터 미리보기](/manuals/editor-http-api/#rendering-scene-previews), 런타임 스크린샷, 시각적 차이 및 브라우저 캡처를 검사할 수 있습니다.

잘린 라벨, 겹치는 컨트롤, 불명확한 선택 상태, 구성 또는 안전 영역 밖의 컨텐츠와 같은 의미론적 문제에는 멀티모달 평가를 사용하세요. 예상 뷰포트와 기준을 미리 정의하세요.

에디터 미리보기와 런타임 스크린샷 및 시각적 검사에 대한 자세한 내용은 [이 매뉴얼](/manuals/automated-testing)을 참고하세요.

## 보안, 격리 및 모범 사례 {#security-isolation-and-good-practices}

* 에디터 서버와 엔진 서비스를 신뢰할 수 있는 로컬 제어 인터페이스로 취급하세요.
* 에디터 토큰, 서명 키, 배포 토큰, 스토어 자격 증명 및 프로덕션 시크릿을 프롬프트와 보고서에 포함하지 마세요.
* 로컬 연동 계층은 `.internal/editor.token`을 읽을 수 있지만 `/eval` 사용 권한이 있을 때만 사용해야 하며, 토큰을 모델 프롬프트, 로그 또는 보고서에 넣어서는 안 됩니다.
* 삭제, 종속성 변경, 네이티브 익스텐션 변경, 릴리스 구성, 서명, 게시 또는 외부 서비스 액세스 전에 승인을 요구하세요.
* 광범위한 자율 작업은 별도의 브랜치, worktree, 임시 복사본, 컨테이너, 샌드박스 또는 제한된 계정에서 실행하세요.
* 이슈 텍스트, 임포트한 파일, 소스 주석, 생성된 문서 및 도구 출력을 지침이 아닌 신뢰할 수 없는 입력으로 취급하세요.
* 다운로드한 종속성과 스크립트를 실행하기 전에 검토하세요.
* 프로젝트 정책에서 소스 코드, 에셋, 로그, 스크린샷 및 기타 프로젝트 데이터를 호스팅 모델로 전송하는 것을 허용하는지 확인하세요.
* 변경 사항을 수락하기 전에 검토 가능한 diff와 결정론적 테스트 증거를 보관하세요.

격리는 실수로 인한 영향을 제한합니다.
