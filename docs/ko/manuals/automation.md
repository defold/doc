# Defold 자동화 {#automation-in-defold}

이 매뉴얼에서는 전반적인 내용을 설명하고 각 주제의 개별 매뉴얼로 연결되는 링크를 제공합니다.

Defold는 여러 수준의 자동화를 지원합니다. 작업에 적합한 인터페이스를 선택하는 일은 효과적인 자동화에서 가장 중요한 요소 중 하나입니다. 아래 표를 참고하면 각 동작에 가장 간단한 인터페이스를 선택할 수 있습니다.

| 계층 | 용도 |
| --- | --- |
| [에디터 스크립트](/manuals/editor-scripts) | 테스트와 개발 속도를 높이기 위한 커스텀 명령 및 에디터 워크플로우 또는 연동 기능(예: 레벨, 에셋 생성) |
| [에디터 UI 스크립트](/manuals/editor-scripts-ui/) | 에디터 스크립트를 활용하는 커스텀 시각 도구, 팝업, 구성 도구 또는 유저 인터페이스 |
| [에디터 HTTP API](/manuals/editor-http-api) | OpenAPI 동작, 프로젝트 리소스, 빌드, 에디터 명령, 미리보기, 환경 설정, 콘솔 출력이나 커스텀 동작을 위한 에디터 스크립트를 통해 Defold 에디터에서 열린 게임 프로젝트 제어, 외부 도구 및 IDE 연동, 테스트 컨트롤러 |
| [Bob CLI](/manuals/bob) | 커맨드 라인에서 프로젝트 빌드, 데이터 아카이브 또는 standalone 번들 생성, 보고서, CI |
| [라이프사이클 훅](/manuals/editor-http-api#lifecycle-hooks) | 에디터 빌드 또는 번들링 전후의 검증이나 생성 |
| [엔진 HTTP 서비스](/manuals/engine-service) | 실행 중인 Defold 게임엔진(`dmengine`) 검사, 개발 서비스, 프로파일링, 런타임 메세지, 익스텐션에서 정의한 런타임 자동화 API, 실행 중인 디버그 빌드를 조회하고 명령을 전송하는 외부 도구 |
| [Automation Bridge](https://github.com/defold/extension-automation-bridge) | 추가 엔진 런타임 자동화 엔드포인트를 제공하는 공식 Defold 익스텐션 |
| [자동화 테스트](/manuals/automated-testing) | 게임 로직, 메세지, 컴포넌트, 입력, 물리 및 엔진 동작 테스트, 씬 검사, [에디터 미리보기](/manuals/editor-http-api/#rendering-scene-previews) 등을 통한 시각적 피드백, 입력 주입, 실시간 어플리케이션 상태, [실행 중인 테스트 컬렉션](/manuals/automated-testing/#tests-in-a-running-collection) |
| 셸 스크립트 또는 태스크 러너 | 생성, 포멧팅, 검증 및 반복 가능한 작업, 일반 파일 작업 |
| 외부 플랫폼별 도구 및 웹 브라우저 자동화 도구 | 데스크톱 테스트 도구, HTML5 상호작용 테스트, 스크린샷, 웹 연동 |
| AI 코딩 에이전트와 멀티모달 모델 | 결정론적 방식으로 구현하기 어렵거나 불가능한 작업, 씬, GUI 레이아웃 또는 런타임 스크린샷의 의미론적 분석 |

가장 중요한 차이는 Defold 에디터와 실행 중인 게임 사이에 있습니다. 두 항목은 각각 별도의 HTTP 서버를 사용하는 별도의 프로세스입니다.

## 결정론적 자동화 또는 AI 에이전트 {#deterministic-automation-or-ai-agents}

레벨 검증 도구, 포멧터, 빌드 작업 또는 회귀 테스트처럼 작업 순서가 이미 정해져 있다면 결정론적 해결책을 우선하세요. 이러한 작업에는 일반적으로 안정적인 입력, 출력, 타임아웃 및 종료 코드가 있어야 합니다. CI에서 안정적으로 실행할 수 있는 자동화 훅과 테스트에 적합합니다. 예를 들어 gltf 오브젝트를 주어진 메터리얼이 적용된 모델로 변환하거나 레벨에 나무 등을 배치하는 도구와 같이 프로젝트 리소스를 절차적으로 생성할 때도 결정론적 해결책을 사용하는 것이 좋습니다. 에디터 스크립트와 UI를 사용하면 프로젝트마다 이러한 절차를 쉽게 만들 수 있습니다. 자세한 내용은 [매뉴얼](/manuals/editor-scripts-ui)을 참고하세요.

리소스 찾기, 구현 방식 선택, 여러 파일 수정, 오류 해석, 정의된 승인 기준을 충족할 때까지 반복하는 작업처럼 조사 또는 멀티모달(예: 시각 자료 포함) 분석이 필요할 때 에이전트가 유용할 수 있습니다. 하지만 에이전트도 결정론적 인터페이스를 호출하고 로컬 스크립트나 CI 러너와 동일한 증거를 사용해야 합니다. [Defold에서 AI 코딩 에이전트 사용하기](/manuals/ai-agents) 매뉴얼을 참고하세요.

## 자동화 루프 {#the-automation-loop}

신뢰할 수 있는 자동화 프로세스는 다음과 같은 폐쇄형 루프를 구성합니다.

1. 검사 - 프로젝트 파일, 현재 인터페이스 설명 및 관련 문서를 읽습니다.
2. 변경 - 에디터 트랜잭션, 에디터 스크립트 또는 파일과 셸 도구를 사용합니다.
3. 검증 - 빌드하고, 집중 테스트를 실행하고, 로그, 보고서, 상태 또는 이미지를 수집합니다.
4. 평가 - 증거를 승인 기준과 비교한 다음 완료하거나 다시 시도합니다.

![검사, 변경, 검증 및 평가로 구성된 자동화 루프](images/automation/automation_loop.png)

검증에서는 실제 환경의 증거를 제공해야 합니다. 적합한 증거는 다음과 같습니다.

* 성공한 빌드 결과
* 명시적으로 완료된 테스트 스위트
* 실행 중인 게임에서 확인한 예상 상태
* 생성된 번들 또는 빌드 보고서
* 결정론적 이미지 비교
* 정의된 시각적 기준을 충족하는 스크린샷

변경하기 전에 예상 결과를 정의하세요. 타임아웃과 최대 복구 시도 횟수도 정의하세요. 무인 프로세스가 승인 기준을 충족하지 못할 때 무한히 계속되어서는 안 됩니다.
